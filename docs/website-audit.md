# Website audit and Careers delivery

11 October 2026. Audited the repository and local previews of every implemented website route: gateway, home, about, industries, both service pages, contact, Careers and recruitment administration. This is a code/content/functional review with local verification, not a penetration-test certification of the live hosting environment or third-party Team Hub.

## Careers implementation

- Branded editorial page, project-specific copy and realistic no-vacancy/outage states. No fabricated vacancy is published.
- Desktop/mobile/drawer/footer Careers links. Public roles refresh from the database without a rebuild. Expired/closed roles disappear and are checked again before application dispatch.
- Search plus region/contract filters; complete description and requirement disclosure; application selects an actual role.
- Admin role/certification/location/industry/contract/start/working-pattern catalogues with Other + typed values, 40 grouped requirement choices, custom requirements, headcount, duration, optional closing date, draft/publish/close/archive, advert preview, pagination and competing-edit protection.
- Contact details, email/call/WhatsApp preference, availability, cover letter and one PDF CV (5 MB). No public account, CV archive, applicant table or email-attachment URL.
- Requested vacancy-availability and unsolicited-CV disclaimers; Description/Requirements cover-letter guidance; Apply / Chat / Prove It / Level Up sequence adapted to first assignment.
- Four-category, sixteen-question FAQ based on the supplied tabbed-explorer pattern. Removed unrelated billing/AI demo copy, missing UI imports, `any` icon type and excessive shadows. Keyboard arrows/Home/End, native one-at-a-time disclosures, typed content, responsive layout. No npx component installer was needed.

## Verification and limits

- Lint, TypeScript and production build pass. Production dependency audit: zero advisories; full development/tooling audit: five high.
- `npm run test:careers`: real embedded PostgreSQL validates the SQL migration, grants/RLS, public visibility, password-only/outsider/stale-MFA/revoked-member/removed-factor/revoked-session rejection, close/edit lifecycle, audit and shared limiter. Pure-model tests cover required fields, custom requirements, invalid values and PDF boundaries.
- Delivery tests run the actual handler and stream reader with Supabase HTTP, CAPTCHA, scanner and email HTTP mocked. Confirm fixed reception recipient, reply-to, PDF bytes, role/requirements/cover email content, stable identical retry keys, oversize/chunked input rejection, invalid PDF/consent/CAPTCHA, rate limits, closed roles, closure during scan, scanner failures and delivery failures. No real CV was processed or email sent.
- Production HTTP audit checks nine pages, one h1 per route, duplicate IDs, every linked internal fragment and 110 resources; no broken internal destinations/assets. Invalid unauthenticated/cross-origin requests are refused. Evidence: `docs/qa/website-audit.json`.
- Browser checks at 390, 768 and 1440 px cover eight website/admin routes; gateway covered by HTTP and previous integration evidence. No failed images or unlabelled form controls detected. Home overflow was subsequently corrected and rechecked. Evidence: `docs/qa/website-responsive-checks.json`.
- Browser exercised admin select/Other, requirement checkboxes and advert preview with clearly labelled test-only content and disabled saving; mobile Careers nav, FAQ category switching, disclosure and keyboard arrows/Home. Saved desktop/mobile previews are in `docs/qa/careers-*.png`.
- No full screen-reader, colour-contrast, real-device Web Vitals, real Supabase identity, production TLS/WAF, live malware scanner or actual reception-mailbox delivery test is claimed. Those are explicit gates in [the production plan](careers-production-plan.md).

## What prevents production today

Provide/configure a staging Supabase project and verified accounts; run the migration and controlled bootstrap; connect a private non-retaining scanner, Turnstile and a verified Resend recruitment sender; select hosting and check its upload limit/trusted headers; approve privacy/mailbox procedures; complete the live negative-security and delivery tests. The repository contains the configuration template and implementation, but no live credentials or services have been invented. Nothing has been deployed, committed, pushed or published by this task.

The detailed launch sequence, test matrix, recovery concerns and provider sources are in [careers-production-plan.md](careers-production-plan.md).
